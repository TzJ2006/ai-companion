# The idea graph — format

One file holds everything: `ideas/graph.yaml` — unless that name is already
taken by another companion, in which case this one uses `ideas/graph.cursor.yaml`
(Claude: `.claude`, Codex: `.codex`). Same rule for `log.md` and `graph.html`.
`ideas.ts paths` prints the resolved names. Ownership is the `agent:` key at the
top of the graph file.


Every idea in a project is one node. Every prerequisite is one arrow. There is
no second document, no requirement/feature/module/function hierarchy, no phase
vocabulary. If it isn't in this file, it isn't tracked.

## A node

```yaml
- id: I-014
  name: "函数级变更追踪"          # short — this is all the graph shows
  status: todo                    # todo | doing | done | blocked
  needs: [I-003, I-008]           # prerequisites — the only kind of edge

  what: >
    这个想法是什么。
  why: >
    为什么有这个想法。
  expected: >
    这个想法的预期结果是什么。
  how: >
    要如何实现这个想法。
  why_this_way: >
    为什么要这样实现这个想法。
  code:                           # 这个想法的具体实现的代码在哪个文件的哪几行
    - file: packages/ast/src/identity.ts
      symbol: computeFunctionIdentity
      lines: "12-48"
  verify:                         # 当这个想法实现了之后要如何验证这个想法就是我想要的预期结果
    command: npx vitest run tests/identity.test.ts
    pass: "exit 0"
  future: >
    这个想法所实现的东西未来可以如何使用。

  log:                            # append-only；谁改了它、为什么
    - date: "2026-08-24"
      by: idea-build
      note: "implemented; lines 12-48"
```

## The eight questions

| # | 问题 | 字段 |
|---|------|------|
| 1 | 这个想法是什么 | `what` |
| 2 | 为什么有这个想法 | `why` |
| 3 | 这个想法的预期结果是什么 | `expected` |
| 4 | 要如何实现这个想法 | `how` |
| 5 | 为什么要这样实现这个想法 | `why_this_way` |
| 6 | 这个想法的具体实现的代码在哪个文件的那几行 | `code` |
| 7 | 当这个想法实现了之后要如何验证这个想法就是我想要的预期结果 | `verify` |
| 8 | 这个想法所实现的东西未来可以如何使用 | `future` |

**When each is answered.** 1–5, 7 and 8 are answered *before* any product code
exists — that is what makes an idea reviewable. Question 6 is answered twice:
`file` and `symbol` are the plan (where the code *will* go, decided by
`/idea-discuss`), `lines` are the truth (filled by `/idea-build` once it exists).
`/idea-debug` compares the two.

**`verify` has two forms.** Prefer the first:

```yaml
verify: { command: "npx vitest run tests/x.test.ts", pass: "exit 0" }
verify: { manual: "打开报告，图里每个节点都能点开", signed_off: null }
```

A `manual` check can never be marked `done` by a machine. It stays open until a
human writes their name and the date into `signed_off`. That is the whole rule.

## The file

```yaml
version: 1
project: my-project
overview: >
  一段话说清这个项目在做什么。
endpoints: [I-022, I-030]     # 终点：什么叫"这个项目做完了"

ideas:
  - id: I-001
    ...
```

- **IDs** are `I-NNN`, sequential, **never reused** — not even for an idea that
  was abandoned. An abandoned idea keeps its id and gets `status: blocked` with
  a `log` entry saying why.
- **`endpoints`** are the terminal deliverables. Everything else exists to reach
  one of them. An idea that reaches no endpoint is either dead work or evidence
  of a missing endpoint — `check` will tell you which ideas those are.
- **The graph must be acyclic.** A cycle means two ideas are actually one idea.
  Merge them, keep the lower id, log the merge.
- **The frontier** — `todo` ideas whose `needs` are all `done` — is your
  next-actions list. It falls out of the data; there is no separate TODO file.
- **Edges** — if idea A is a prerequisite of idea B, A appears in B's `needs`,
  and the HTML graph draws an arrow from A to B.

## The harness (write-gate)

Product code is locked until an idea is `doing`. The Cursor `preToolUse` hook
calls `decideWrite` on every Write / StrReplace / Delete. Fail closed.

```yaml
enforce: true          # default. `ideas.ts enforce off` to disable
exempt:                # optional prefixes the gate will not block
  - cursor-companion/**
```

**Always allowed:** this companion's ledger (`ideas/graph.yaml` or, if taken,
`ideas/graph.cursor.yaml`, plus the matching `log` / `html`). Never the other
agent's files.

**Unlocked only while `doing` and build-ready:** files in that idea's `code`
plus path tokens in `verify.command`. Build-ready means `how`, `expected`,
`verify`, and `code.file` are filled, and every `needs` is `done`. Two `doing`
ideas may not share a `code` file.

**`set done` runs `verify.command`.** If it fails, status stays put. `--force`
skips the run and logs `FORCED`. A `manual` verify still needs `signed_off`.

**Locked:** `.cursor/hooks.json` and the gate scripts — the agent cannot
uninstall the harness. Edit `cursor-companion/` and reinstall, or `enforce off`.

## Generated files

```
ideas/graph.yaml          ← default ledger (agent: cursor)
ideas/graph.cursor.yaml   ← used instead if graph.yaml is already someone else's
ideas/graph.html          ← generated by `ideas.ts render` (same suffix as the yaml)
ideas/log.md              ← append-only (log.cursor.md when the graph is suffixed)
```

## The engine

After install, always:

```bash
npx tsx .cursor/companion/ideas.ts check
npx tsx .cursor/companion/ideas.ts next
npx tsx .cursor/companion/ideas.ts show I-014
npx tsx .cursor/companion/ideas.ts new "短名称" [--needs I-001,I-002]
npx tsx .cursor/companion/ideas.ts set I-014 done --by idea-build --note "..."
npx tsx .cursor/companion/ideas.ts allow src/foo.ts
npx tsx .cursor/companion/ideas.ts enforce on|off
npx tsx .cursor/companion/ideas.ts log --by idea-build --ideas I-014 --files src/a.ts --note "..."
npx tsx .cursor/companion/ideas.ts render
npx tsx .cursor/companion/ideas.ts init
```

Every command takes `--file <path>` (default: the resolved graph) and
`--project <dir>` (default the current directory). `ideas.ts paths` shows which.

Fallback if this project has not been installed yet:
`npx tsx cursor-companion/ideas.ts <command>`.

## Why this shape

One node type, because every 想法 is a module in the same graph. One edge type,
because "A 是 B 的前置" is the only relation. Eight fields, because those are
the eight questions, in that order. Anything the format does not hold is
something that was not asked for, and adding it later costs one YAML key.
