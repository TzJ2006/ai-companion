# ccfix — 是代码错了，还是想法过时了

先读引擎旁边的 FORMAT.md。查错有先后：**先对图，再质疑图**。

## 第 1 步 — 代码对照想法

```
node .claude/companion/companion.mjs show I-0XX
```

把 `what` / `how` / `why_this_way` / `expected` / `needs` 逐条对照真实代码
（`code` 里有文件和行号，行号过期本身就是一个发现）。**每条不一致都必须带
文件和行号引用 —— 不带引用的发现不算发现。**

三种结局：
- **代码偏离想法** → 改代码对齐图，跑 `run-check I-0XX --phase green` 收尾。
- **想法过时了** → 这是图的修改：更新想法的叙述，记 log，改动大到换了意思
  就回 ccthink 重新过批准。
- **两边都对但行为不对** → 进第 2 步。

## 第 2 步 — 用真实输入输出质疑想法

跑最小的真实复现：真实输入、真实输出，贴原文。假设要一个一个立、一个一个
杀，每个假设先说清「如果它成立，我会看到什么」。修不动的：

```
node .claude/companion/companion.mjs set I-0XX blocked --note "卡在哪，试过什么"
```

把 blocked 的原因写全 —— 下一个接手的人（或下一轮的你）只有这条记录可读。

## 规矩

- 修好一个想法弄坏另一个，不叫修好 —— 收尾必须全套测试绿。
- 绝不为了让测试过而改测试；测试真的错了，那是拿给人看的发现。
- 每一步都记进想法旁的 log：日期、试了什么、结论。
