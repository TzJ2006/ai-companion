# ccgraph — 图长什么样，现在能做什么

先读引擎旁边的 FORMAT.md，遵循 D33「目标授权、提问与交接」和「主线、交付三段、拒绝分类与记录分档」。
状态汇报本身用 D33「执行中进度块」的七行开头（主任务/当前情况/正在做/已完成/还差什么/下一步/需要你决定）。
看图是只读的：图上的历史错误报告出来即可，不因此改图，也不被它拦住结束（I-150）。

## 参数

一个想法编号就只看那一个（`show I-0XX`）；`--check` 只报问题、不渲染。
不带参数就是校验、渲染、汇总。

## 全都跑一遍

只读命令，按这个顺序跑：

```
node .companion/companion.mjs check
node .companion/companion.mjs render
node .companion/companion.mjs next
node .companion/companion.mjs status
node .companion/companion.mjs paths
```

先按 D33「交付三段」说：目前完成了什么（依据是想法的 log 和验证记录）、agent 接着该做什么、
人现在需要做什么（等人签字的想法列出来，没有就写不需要）；没有会话记录时明确说未知，
不能把 doing 当作实际执行到了哪一步的证明。然后按需要展开四件事：

1. **图的画像** — 多少个想法、几个完成、终点是什么、网页在哪
   （路径以 paths 打印的为准，不许猜文件名）。
2. **错误和警告** — `check` 的输出按严重程度排：错误必须修（说清哪条命令修），
   警告逐条说要不要理。
3. **前沿** — `next` 列出的想法就是现在能动手的；每个配一句它是什么。
4. **卡住的** — blocked 的想法和它们各自在等什么：`status` 只给编号和名字，
   原因要用 `show <id>` 看它的受阻原因和最后几条修改记录。

最后说明下一步如何推进目标，需要时附命令，不要求人批准这份状态汇报。

**这条工作流禁止修任何东西** —— 发现问题只报告：图的问题指给 ccthink 或
ccfix，代码的问题指给 ccbuild 或 ccfix。看单个想法用
`node .companion/companion.mjs show I-0XX`。用户单独请求看图，交付报告后结束；
若只是已授权工作中的状态查询，回答后回到原任务，不重新索取继续工作的批准。

## 同目录协作（只读）

`node .companion/companion.mjs coord status` 说三件事：协作模式开没开、守卫是在写前核对归属
还是只有命令约定、哪些文件归哪个会话。报告里照实说 —— 没开就是「只有约定」，不写成受保护。
`coord inbox --session <身份>` 只读消息，不代人 ack。
